## 메타데이터 해석의 한계

- 정의의 정적 의존성과 동적 SQL 내에 드러난 객체명을 추적했다. 데이터베이스의 실행 시 문맥·분기·암호화·CLR 구현까지 모두 재현한 것은 아니다.
- 동적 SQL·주석·별칭에서 추출한 후보 중 일부는 일반 이름이나 시스템 뷰로 해석되어 메타데이터가 조회되지 않았다. 이를 실제 업무 테이블 미존재로 단정하지 않는다. 예: `no`, `contents`, `file_name`, `title`, `name`, `tel`, `cd` 같은 별칭 후보.
- SQL Server 시스템 객체 일부는 사용자 `sys.objects`와 다른 카탈로그에 있으며 내부 구현은 이번 업무 객체 조사 대상에서 제외했다.
- 관련 참조 후보 `SmartBill3.dbo.TAX_EVENT`, `SmartBill3.dbo.DTI_MAIN`, `SmartBill3.dbo.DTI_STATUS`는 정의·실체를 확정하지 못했다. 동적 SQL의 실제 대상 및 개발 환경 잔존 참조인지 DB 담당 확인이 필요하다. 직접 호출 객체 자체의 조회 실패를 뜻하지 않는다.
- 결과 컬럼은 Mapper의 명시 Result 매핑과 VO를 근거로 기록했다. 저장 프로시저를 실행하거나 `sp_describe_first_result_set`로 동적 분기를 컴파일하지 않았으므로 모든 런타임 결과셋/별칭을 독립 보증하지 않는다.
- RETURN 식은 정의 본문, OUT은 sys.parameters와 Mapper 바인딩을 함께 기록했다. SQL 타입 별칭은 DB에 선언된 별칭 이름을 유지했다.
