# 개발 도구와 저장소 준비

## 필요한 도구·접근

| 준비 | 기준 | 확인 방법 |
|---|---|---|
| Git·GitHub | thebusinesson/smartwork 저장소 읽기 및 작업 브랜치 쓰기 권한 | clone·원격 확인 |
| Node.js | 22 계열 | `node --version` |
| Yarn | Classic 1.x | `yarn --version` |
| JDK | Java 17; JRE만 설치하면 컴파일 불가 | `java -version`, `javac -version` |
| Gradle | 프로젝트 Wrapper 사용 | backend에서 `./gradlew --version` |
| 사내 네트워크 | 승인된 개발 DB·연계 서버 접근 경로, 필요 시 VPN | DB·연계 담당에게 대상·방화벽 확인 |
| 다운로드 경로 | GitHub·Node 패키지 registry·Maven/Gradle 저장소 접근 | 의존성 설치 오류 시 사내 proxy/CA 설정 확인 |

Node.js 22와 JDK 17은 사내 표준 설치 방법으로 준비한다. Java를 여러 버전 설치했다면 터미널의 JAVA_HOME과 IDE의 Project SDK·Gradle JVM을 모두 17로 맞춘다. WSL 예시를 사용할 때는 Linux 셸 안의 Node·Java·Yarn을 확인하고 Windows 실행 파일과 경로가 섞이지 않게 한다.

배포 workflow는 Corepack을 켜고 Yarn을 사용한다. Corepack이 제공되는 Node 설치에서는 다음으로 Yarn 실행을 활성화한다.

```bash
corepack enable
yarn --version
```

`yarn --version`이 1.x인지 확인한다. Corepack이 없는 배포판은 사내 표준 방식으로 Yarn Classic을 설치한다. 이 작업을 위해 저장소를 다른 Yarn 메이저 버전으로 전환하거나 lockfile을 다시 만들지 않는다.

## 저장소 받기

다음은 새 디렉터리에 처음 받을 때의 예시다. 이미 checkout한 저장소가 있다면 그 위치를 사용한다.

```bash
mkdir -p ~/dev/repo
cd ~/dev/repo
git clone https://github.com/thebusinesson/smartwork.git
cd smartwork
git status --short
git remote -v
```

인증은 조직에서 허용한 GitHub 로그인·credential helper·SSH 구성을 사용한다. 토큰을 clone URL이나 README에 넣지 않는다. HTTPS push에 인증이 없다는 오류가 나면 사용 중인 credential helper 또는 GitHub CLI 로그인 상태를 확인한다.

## 로컬·IDE 확인

```bash
node --version
yarn --version
java -version
javac -version
cd backend
./gradlew --version
```

Gradle 배포본은 Wrapper가 내려받으므로 전역 Gradle 설치는 필요 없다. `gradlew` 실행 권한이 없는 checkout은 실행 권한을 확인하고, 파일이 CRLF로 변환된 경우 저장소의 줄바꿈 규칙을 복원한다.

IDE는 저장소 전체를 열고 backend를 Gradle 프로젝트로 인식시킨다. Kotlin·Spring 라이브러리는 Gradle import로 받는다. `backend/libs`의 로컬 SDK JAR도 빌드 입력이므로 누락·임의 교체 여부를 확인한다.

| 경로 | 역할 |
|---|---|
| frontend/src/app | 앱 시작점·메뉴·라우트 |
| frontend/src/feature | 업무 도메인 화면·API·Hook |
| frontend/src/shared | 공통 UI·HTTP·상태·권한 |
| backend/src/main/kotlin/com/bizon/smartwork/api | Controller·DTO |
| 같은 루트의 core / infra | 업무·영속성 / 설정·보안·공통 인프라 |
| backend/docs/sql | smartwork DB의 테이블·프로시저 정의 관리 |
| docs | 업무·운영·레거시 분석 |
| logs, frontend/dist, build | 생성 결과; 소스와 구분 |
