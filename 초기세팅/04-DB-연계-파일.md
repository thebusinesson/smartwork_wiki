# DB·외부 연계·파일 준비

## DB 접속과 권한

현재 기본 데이터소스는 SQL Server이며 primary JPA·JdbcTemplate와 업무 Mapper가 이를 사용한다. 로컬 앱을 켜기 전 사내 네트워크·접속 계정·DB 권한을 준비한다. PostgreSQL 드라이버가 의존성에 포함되어 있다는 이유만으로 모든 개발 PC에 PostgreSQL 설치를 필수로 요구하지 않는다. Redis도 현재 초기 실행의 필수 설치 항목으로 임의 추가하지 않는다.

| 준비 항목 | 확인할 내용 |
|---|---|
| 연결 대상 | 승인된 개발 서버와 DB 이름. local 기본 연결을 그대로 쓸지 별도 검증 DB를 쓸지 결정 |
| 환경변수 | local URL의 DB_HOST·DB_DATABASE, 인증의 DB_USERNAME·DB_PASSWORD. 비밀값은 승인된 방식으로 주입 |
| 네트워크 | 회사망/VPN·방화벽·DNS와 해당 SQL Server 접속 포트 |
| DB 권한 | primary smartwork DB뿐 아니라 실제 호출 SP가 접근하는 SmartBill3·SB_DTI·Office 등 해당 교차 DB 권한 |
| 스키마·프로시저 | 코드가 호출하는 객체가 해당 환경에 적용되어 있는지 DBA와 대조 |
| 인증 관련 데이터 | 사용자·조직·권한 데이터가 준비되어 있고 검증 계정에 메뉴·작업 권한이 부여되어 있는지 |

local JDBC 설정의 encrypt·trustServerCertificate 등은 YAML 원본을 따른다. 접속 비밀이나 서버별 값을 문서에 복제하지 않는다. SQL Server 정의 조회에 sqlcmd를 사용할 때는 서버 지정 직후 `-C`를 붙이는 사내 mssql-onprem 규칙을 따른다. 이 초기세팅 문서를 위해 실제 DB 접속·변경을 실행하지 않았다.

## SQL 파일을 적용하기 전에

backend/docs/sql은 smartwork DB에 생성할 테이블·프로시저의 정의를 관리한다. 저장소를 clone했다고 모든 .sql을 일괄 실행하는 설치 스크립트가 되는 것은 아니다. 이미 적용된 객체·환경별 차이·실행 즉시 데이터를 바꾸는 예외 파일이 있으므로 DBA가 적용 대상을 판단한다.

비-smartwork DB의 DDL은 backend/docs/sql/dba/dba-legacy-ddl-changes.sql에 모으며, smartwork SP 안에서 다른 DB를 읽거나 호출할 수 있다. 새 개발 DB를 만들더라도 SQL Server 하나와 빈 smartwork DB만으로 모든 레거시 업무가 재현되는 것은 아니다.

## 외부 연계 사용 범위

| 연계 | 초기 준비와 확인 |
|---|---|
| RabbitMQ·메일 | local은 개발 메일 브로커와 소비자가 연결되는 구성. 실제 발행 경로·수신 대상·테스트 전환을 담당자와 확인 |
| mail-service.test-redirect | 현재 local에는 true지만 발행을 중지하는 옵션이 아님. 구현은 수신자 처리·발행 방식을 바꾸므로 소비자·최종 발송까지 함께 확인 |
| 결제 PG | local 설정은 test 플랫폼이나 실제 사용하는 가맹점·키·연계 주소와 수동/예약 실행을 구분 |
| 채권잔액 재전송 등 | 기능별 외부 클라이언트·환경·대상 업체 확인. 로컬 앱 실행만으로 격리되지 않음 |
| 스마트빌 레거시 링크 | 프런트 VITE_SMARTBILL_BASE_URL과 실제 개발/데모/운영 이동 대상 일치 확인 |

수신처와 테스트 데이터가 준비되지 않은 상태에서는 저장·삭제·발송·초기화·결제·재전송을 세팅 확인용 버튼으로 사용하지 않는다. 격리 검증은 별도 DB·파일 영역과 테스트 수신처/샌드박스·확인 가능한 결과 기록을 준비해서 진행한다.

## 파일 저장소와 양식

앱이 기동된 것과 기존 첨부파일이 조회되는 것은 별개다. 로컬 빈 저장소에는 공유 서버의 실제 첨부·인감·통계 파일이 자동으로 내려오지 않는다. 사용할 기능에 필요한 루트·원본·실행 계정 권한만 준비한다.

| 설정 | 사용 업무 |
|---|---|
| storage.sbadmin | 공통 업로드·생성 파일·회원 업로드 원본 |
| storage.drc | 채권잔액 확인서 첨부 |
| storage.comseal | 회사·전자계약·세금계산서 미리보기의 인감 이미지 |
| storage.part-ask | 제휴 문의 첨부 |
| storage.tax-invoice-attachments | 세금계산서 원본 첨부 |
| storage.support-file-pds | 고객 자료실·플랫폼 게시판 등 첨부 |
| storage.templates | 다운로드 양식 |
| storage.attachments | 연동·오류 관리 첨부 |
| storage.statistics | 통계 누적 마스터 엑셀 |
| storage.banner | 공개 배너 이미지 |

원본 파일을 다운로드하지 못한 범위나 이관·적용 보류 결정은 소스의 스토리지 가이드를 따른다. 초기 세팅을 위해 운영 파일을 임의 복사하거나 공유 마운트·권한을 변경하지 않는다. 빈 폴더 생성만으로 파일 이관·다운로드 성공을 표시하지 않는다.

## Docker와 배포의 범위

Docker는 일반적인 yarn dev·bootRun 실행에 필수가 아니다. docker-compose.dev.yml은 개발 서버의 frontend·backend 앱과 마운트를 운영하는 구성으로, 업무 DB·외부 메일·파일을 모두 로컬에 복제하는 세트가 아니다. 로컬 초기세팅과 개발 서버 기동·배포를 구분한다.

main의 관련 경로 변경은 개발 배포 workflow의 실행 조건이며, 데모·신규 DB 개발·운영은 별도 수동 workflow를 사용한다. 배포할 때는 [배포 가이드](https://github.com/thebusinesson/smartwork/blob/dc216b3130faabcfc1dce7dbc9bd2e3b8fbecefc/docs/operations/deployment-guide.md)와 [workflow 원본](https://github.com/thebusinesson/smartwork/tree/dc216b3130faabcfc1dce7dbc9bd2e3b8fbecefc/.github/workflows/)을 따른다. 이 문서 작성으로 서버·DB·마운트·배포를 변경하지 않았다.
