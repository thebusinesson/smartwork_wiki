# Backend 초기세팅

## 실행 전 확인

Java 17을 준비하고 [DB·연계·파일](04-DB-연계-파일.md)의 접근 조건을 확인한다. 기본 프로필은 application.yml에 지정된 local이며 application-local.yml이 추가 적용된다. local의 DB는 기본적으로 공유 개발 서버다.

접속값은 IDE Run Configuration의 환경변수 또는 승인된 비밀 주입 방식으로 설정한다. Spring Boot가 frontend/.env나 임의의 backend/.env를 자동으로 읽는다고 가정하지 않는다. 환경변수 이름·기본값은 프로필 YAML이 원본이며 실제 계정·비밀번호는 이 문서에 복제하지 않는다.

## 기본 명령과 초기 조회용 실행

README의 기본 실행 명령은 다음과 같다.

```bash
cd backend
./gradlew bootRun
```

현재 local은 인증 우회와 JPA 스키마 자동 갱신 설정을 포함한다. 실제 로그인·권한을 확인하고 공유 DB의 자동 스키마 변경을 피하려는 초기 조회에서는 다음처럼 명시적으로 덮어쓴다. 이 명령은 **DB·외부 연계가 격리된 읽기 전용 서버를 만드는 명령이 아니다**.

```bash
cd backend
./gradlew bootRun --args='--spring.profiles.active=local --security.permit-all-api=false --spring.jpa.hibernate.ddl-auto=none --card-billing.schedule.enabled=false --log-management.aggregation.enabled=false --spring.rabbitmq.listener.simple.auto-startup=false --spring.rabbitmq.listener.direct.auto-startup=false'
```

위 두 예시는 각각 저장소 루트에서 시작한다. 이미 backend에 있으면 cd를 반복하지 않는다. 종료 시 실제 진행 중인 작업이 있다면 해당 업무의 종료 절차를 확인한다.

| 덮어쓰기 | 이유·범위 |
|---|---|
| security.permit-all-api=false | local의 기본 true 대신 실제 인증·권한 검사 사용 |
| spring.jpa.hibernate.ddl-auto=none | local의 update로 인한 스키마 자동 변경 방지; 프로시저·업무 데이터 쓰기는 별도 |
| card-billing.schedule.enabled=false | 자동결제 예약 실행을 켜지 않음; 수동 결제 API를 차단하는 설정은 아님 |
| log-management.aggregation.enabled=false | 로컬 실행 중 정기 집계를 하지 않도록 설정 |
| RabbitMQ listener 자동 시작 false | 해당 리스너 소비 자동 시작을 막는 설정. 메시지 발행·외부 API 호출 자체를 차단하지 않음 |

일부 작업은 앱 시작 이벤트에서 활성 Job을 조회·복구한다. 예를 들어 BulkReceiptIssueJobLauncher는 ApplicationReadyEvent에서 활성 영수 대량발행 Job을 찾아 실행한다. 위 설정만으로 모든 시작 작업이 중지되는 것은 아니므로 공유 DB 사용 전 담당자와 진행 중 Job·기동 영향을 확인한다.

## 주소와 인증

| 항목 | 기본 주소 |
|---|---|
| API | <http://localhost:8080> |
| Swagger UI | <http://localhost:8080/swagger-ui.html> |
| OpenAPI JSON | <http://localhost:8080/v3/api-docs> |
| Frontend | <http://localhost:5173> |

기동 로그에서 실제 프로필·포트를 확인한다. 로그인된 API 조회는 검증 계정의 메뉴·액션 권한도 필요하다. 인증 우회가 꺼진 상태의 401·403을 DB 연결 오류로 단정하지 않는다. 임의의 다른 프런트 포트는 허용 CORS Origin과 쿠키 조건을 함께 확인한다.

## 컴파일·테스트·빌드

backend 디렉터리에서 실행한다.

```bash
./gradlew compileKotlin
./gradlew test
./gradlew build
```

Backend README에는 build를 테스트 포함으로 설명하지만, 실제 build.gradle.kts의 Test 태스크는 요청 태스크 이름에 test 또는 :test가 있을 때만 동작한다. `build` 성공만으로 테스트 실행을 확인하지 말고 `./gradlew test` 결과를 별도로 남긴다.

여러 모듈 중 **루트 앱의 특정 테스트만** 실행할 때는 절대 태스크 경로를 사용한다.

```bash
./gradlew :test --tests '*MenuPermissionAspectTest'
```

`./gradlew test --tests ...`는 서브프로젝트에도 필터를 적용해 해당 모듈에 일치하는 테스트가 없다는 실패를 낼 수 있다. 실제 DB·외부 시스템을 쓰는 통합 테스트는 대상 환경·fixture의 부작용을 확인한 뒤 실행한다.

배포용 JAR 생성은 `./gradlew bootJar`이며 테스트 성공과 별개의 결과다. Kotlin·Spring·Gradle 버전은 프로젝트 설정과 Wrapper를 사용하고 IDE가 임의 버전으로 바꾸지 않게 한다.
